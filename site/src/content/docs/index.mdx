Astera is a desktop app that runs many Claude Code and Codex terminals for you. You give it a goal or a source (an
issue, a folder of written plans), a planner splits it into Tasks, and workers run them in parallel, each on the right
model. A reviewer checks every Task, the plan is delivered the way you chose, and Astera asks you only when it must.

## At a glance

<CardGrid>
  <Card title="Parallel workers, one worktree each" icon="code-branch">
    Tasks that do not touch the same files run side by side, and Astera merges finished Tasks itself.
  </Card>
  <Card title="A reviewer on every Task" icon="approve-check">
    A fresh reviewer checks each Task (up to 5 rounds), and a final check compares the result with the goal.
  </Card>
  <Card title="Account rolling" icon="random">
    When an account reaches its usage limit, Astera reads the reset time and resumes the work on the next account.
  </Card>
  <Card title="It asks only when it must" icon="comment">
    Permission prompts, questions and failed reviews wait in one place, **Needs you**.
  </Card>
  <Card title="Real terminals" icon="laptop">
    Every agent is a real `claude` or `codex` terminal. You can watch any of them and type into any of them without
    stopping the rest.
  </Card>
  <Card title="Delivered your way" icon="rocket">
    Per project or per plan: **pr**, **push**, **merge** or **manual**. Astera stops and asks when anything is off, and
    never force-pushes.
  </Card>
  <Card title="Drive it from code" icon="puzzle">
    The `astera` command, an MCP server and a TypeScript SDK all drive the same Host, and plugins run beside it.
  </Card>
  <Card title="Run it elsewhere" icon="server">
    Remote runtimes run sessions and plans on another machine over your own LAN, VPN or Tailscale.
  </Card>
</CardGrid>

## How a plan runs

<a class="astera-diagram" href={`${base}docs/architecture/#the-plan-lifecycle`}>
  <Image src={lifecycle} alt="The life of a plan: a goal goes to the planner, you approve, the coordinator starts workers in waves, a reviewer checks each Task, then a final check and delivery" />
</a>

You write a goal, the planner splits it into Tasks, and you press **Approve & execute**. A coordinator places workers as
their dependencies finish, a reviewer checks each Task, and after the last wave a final check compares the result with
the goal. Then the plan is delivered.
