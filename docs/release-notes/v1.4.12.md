## New features

* **Plugins.** Astera now runs plugins: small Node programs that start with its Host and work beside it, such as one
  that posts failed Runs and open questions to Slack. Settings › Plugins installs one from a folder, or by package name
  from npm. It shows what the plugin is and the permissions it asks for, and you can uncheck any of them before it
  installs. It also lists each plugin with its status, sets its settings and secrets, enables, disables and removes
  it, and opens its log. `astera plugins` does the same from a terminal. Each plugin runs in a process of its own on
  Astera's own Node, so no Node install is needed. A plugin that crashes is started again, and it is marked failed if
  it keeps crashing. Its secrets are hidden in its log. Plugins run trusted code: their permissions limit what they
  ask Astera for, not what they can do on your computer, and the app says so before every install.
* **Plugins by package name, without Node.js.** On a computer without Node.js, Astera fetches npm once, checks it
  against the hash it ships with, and keeps it for later installs. On a company network that blocks
  registry.npmjs.org, the app says so and tells you what to do instead.
* **A guide and a sample for writing plugins.** [docs/plugins.md](https://github.com/parsingk/Astera/blob/main/docs/plugins.md)
  goes from an empty folder to a running plugin: the manifest, each permission, settings and secrets, packaging and
  troubleshooting. The webhook notifier in `examples/plugins` is a working plugin to start from. It posts failed Runs,
  Tasks whose repairs ran out, questions and completed Runs to a webhook, and can sign each post.
* **The Astera SDK.** `@astera-app/client` is a TypeScript client for building on Astera's Host from your own
  programs: a CI step, a bot, a dashboard. It creates and runs Jobs, waits for Runs, answers questions, reads
  completion, and follows the Host's new public event log, which survives restarts. It is not on npm yet. Build it
  from this repository as [docs/sdk.md](https://github.com/parsingk/Astera/blob/main/docs/sdk.md) describes; the
  examples are there too.

## Fixes

* **Sessions taken back after an update keep their tabs.** When the app took back several of the Host's running
  sessions at once, after an update for example, only some of them kept their tabs. Each now gets its tab.
* **The explorer's refresh button keeps your open folders open.** It used to collapse the whole tree. It now reads
  the open folders again and leaves them open.
* **A file name printed before the file exists becomes a link.** When an agent printed a file's name and wrote the
  file afterwards, the name stayed plain text in the terminal. It now becomes a link on your next hover once the file
  is there.
* **A Run driven from an agent session stays with that session.** When a session drives a Run through the `astera`
  command, its workers' questions now wait for that session while it is alive. A roll to another account carries the
  Run over to the new session.
