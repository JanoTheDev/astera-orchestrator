## New features

* **Remote Runtime: run Jobs and sessions on another computer.** Pair this computer with another one that
  has Astera (an office PC, a home server, a VPS) and drive the work there from here. Claude, Codex,
  worktrees and checks all run on that machine, so a Job keeps going when your laptop sleeps, shuts down or
  loses its network. In the app, the Jobs view and the new session dialog let you pick which computer the
  work runs on; from a shell, `astera --runtime <name>`; from MCP, `runtimeId` on every tool. The
  connection is pinned TLS on your own LAN or VPN, with a one-time pairing per controller that is read-only
  unless you pair with full control, and that you can revoke. No Astera server sits in between. Setup,
  security and the recipes that keep it running across reboots are in
  [docs/remote-runtime.md](https://github.com/parsingk/Astera/blob/main/docs/remote-runtime.md).
* **A Run shows the files it changed, from git.** A Run's detail now lists the files the Run changed, read
  from git, beside what its workers reported, and opens each file's diff. It works for Runs on this
  computer and on a paired Runtime, also after the Run's worktree is merged away.
* **Jobs recover with no app open.** When a worker, a repair or a completion check is lost (the Host
  restarted, a process died), the Host now recovers it by itself. Before, that waited for the app to be
  open.

## Fixes

* **Claude Code installed from the app is found.** Claude Code's installer leaves its folder off PATH,
  so after "Install" in the app the app kept saying Claude Code was not installed, and a new terminal
  could not run `claude`. The app now adds that folder to PATH the way Claude Code's own note says
  (the user Path on Windows, your shell's profile file on macOS and Linux), and on macOS and Linux it
  also finds a CLI whose PATH you set in `~/.zshrc` or `~/.bashrc`. On a PC where Claude Code was already
  installed this way, press Install once more.
* **Hooks and the statusline work on Windows without Node.js or Git.** They now run under Astera's own
  runtime, so a PC that has neither still gets session status, notifications and the statusline.
* **Resuming a conversation that went to the background opens where it went.** A Claude conversation
  sent to `/background` continues under a new id. Resuming it from history opened the old copy as it stood
  at the move, or closed the tab at once. It now opens the copy where the conversation continued, and when
  a background session still holds it, offers to take it over.
* **A resumed Claude chat shows its conversation at once,** instead of "no record yet" for a moment.
* **Files Astera could not read are no longer written over.** A settings or state file that could not be
  read (locked, for example) was sometimes taken for a damaged one and replaced. Astera now leaves it
  alone and tries again. Marking a worktree as trusted never replaces a `~/.claude.json` or Codex
  `config.toml` it could not read.
* **Settings keep what you typed.** A field you changed while the settings were still loading kept the
  loaded value. A Slack configuration that could not be read is said so instead of saved over.
* **Smaller fixes in the app.** A dialog closes only for a click that started on its backdrop, so selecting
  text no longer closes it. A tab rename ends once. A pane divider stops where you let it go. The agent
  app mirror is sharp on high density screens.
* **Rolling and Jobs.** A session that exits during an account roll ends there instead of being started
  again on the next account. Pausing a Run keeps a report that arrived at the same moment. A worktree that
  will not delete is tried again later instead of every pass. A coordinator is reminded about the same
  unread messages less and less often, and never while it is at its limit.
* **Lighter over long days.** The Host and the app keep bounded memory over long runs (ended sessions,
  timelines, notifications, caches), stop polling what nobody is looking at, and do slow lookups off the
  main thread. Typing in the file editor and dragging a pane divider no longer redraw the whole window.
* **Background tasks have time limits.** A How It Works agent, a model listing, a CLI install and
  Higgsfield's side calls that run too long are now stopped, with their child processes on Windows.
