## New features

* **Make a Job from a ticket.** The Jobs view has a new **From a source** button. Pick a source, search its items,
  read one, and make a Job from it. The GitHub issues of a project's repository are built in (they need `gh`, logged
  in), and a job source plugin adds others, such as the Linear sample in `examples/plugins`. The Job is named by the
  ticket's title, and a chip on it opens the ticket in your browser. The ticket's text reaches the Job as quoted data,
  not as instructions. `astera sources`, `astera jobs create-from-source` and the MCP tools `list_job_sources`,
  `list_source_items`, `get_source_item` and `create_job_from_source` do the same from a terminal or an agent.
* **Completion checks from plugins.** A Task's checks can now name a plugin beside its run configurations, in the new
  Task window or with `astera tasks add --validate npm-test,plugin:<id>`. A check that fails sends its findings to the
  Task's repair loop. The app shows the check's summary, its findings at their file and line, and a link to the
  plugin's whole report. A check that could not be made, because a service is down or a token is missing, is tried
  once more. Then the Task asks you whether to run the checks again, go on without that check, or mark the Task
  failed. The debug-leftovers sample in `examples/plugins` fails a Task whose changes add a `console.log`, a
  `debugger`, a `TODO` or a `FIXME`.
* **Notifications in your own channels.** A notification plugin is sent each thing worth telling you: a question or a
  session waiting for you, a failed or finished Run, a Task whose repairs ran out, a usage limit, and a session moved
  to another account. Astera words each one in the app's language, so the plugin posts it as it is. A notification
  more than an hour old when its turn comes is not sent. The Discord notifier in `examples/plugins` posts them to a
  Discord channel.
* **Plugins that follow Astera's events.** A plugin can now be handed each of Astera's events in order, and picks up
  where it left off after a restart or while it was disabled. An event whose handler fails is handed over again. The
  webhook notifier in `examples/plugins` now works this way.
* **The plugin SDK for all of these.** `@astera-app/plugin-sdk` 0.2.0 has the helpers for the four kinds of plugin
  above, and `@astera-app/client` 0.3.0 reads a Job's source and the new check results. In a plugin, `ctx.signal` now
  tells a handler that Astera stopped waiting for it, so it can stop its own work too.
  [docs/plugins.md](https://github.com/parsingk/Astera/blob/main/docs/plugins.md) is the guide.

## Fixes

* **On Windows, what a plugin sends from a timer reaches Astera at once.** A call a plugin made from a timer, or an
  answer it gave after waiting on something, waited until Astera next spoke to the plugin, and for ever when it did
  not.
* **On macOS, an update that has to be installed by hand says so in its toast.** When macOS turned a downloaded update
  down, the title bar and Settings said to install it by hand, but the toast still offered a restart that installed
  nothing. It now says the same, with an **Install by hand** button.
* **A plugin that prints without end no longer slows Astera.** A plugin's log takes up to 1,000 lines or about a
  megabyte a second. Past that, lines are counted instead of written, and the last ones before the plugin ends are
  kept, so a crash keeps its stack.
